# Language-analysis boundary — proposal

`Repository snapshot → bounded file and language detection → LanguageAdapter → normalized concept/evidence → deterministic detection → optional AI ambiguity/education layer`. The MVP adapter order is JavaScript, TypeScript, then Python. Future adapters may cover C#, Java, Go, SQL, HTML/CSS, C++, and Rust. No parser is implemented in M0-02A.

Implementation must accept only validated GitHub repository coordinates, never arbitrary remote URLs. Reject URL credentials, non-allowlisted hosts, traversal in repository paths, and files outside the resolved snapshot. Repository files, comments, READMEs, and commit messages are untrusted prompt data. Execute zero analyzed or AI-generated code.

An adapter accepts immutable snapshot metadata and bounded source text; it returns structured syntax facts and candidate normalized concept IDs. Detection source is `rule`, `parser`, or `ai_inferred`. A deterministic hit is still a claim about a specific syntax range, not proof of author knowledge. An AI suggestion cannot become `observed` until a validator confirms a source line reference and sufficient deterministic support; otherwise it remains `inferred` with an explicit label. Do not turn model confidence into a user-facing certainty percentage.

Normalized evidence fields: repository ID, analysis run ID, immutable commit SHA, normalized relative path, start/end line (1-based inclusive), language ID, taxonomy concept ID/version, detector ID/version, `observed | inferred`, optional bounded excerpt digest, and validation status. The client projection additionally includes a secret-redacted snippet of at most 2,000 characters and a truncation flag; it is never a whole-file response. Store exact snapshot provenance so later branch changes do not silently move citations. Validate path containment and line range against the fetched file. Empty/unsupported/binary/oversized files yield explicit skip reasons. Multiple evidence refs may support one concept; one ref may link several concepts.

Deterministic responsibilities: URL/size/language detection, syntax extraction, known pattern recognition, deduplication, evidence range validation, answer-key scoring, and stable taxonomy mapping. AI responsibilities: clarify ambiguous patterns, explain selected code, generate and evaluate educational prose. AI output is schema-validated and evidence-checked; ungrounded claims are rejected or labeled inferred. Repository text, README/comments, commits, and external content are untrusted prompt data, never instructions. No arbitrary code execution.

Tests before adapter work: strict GitHub URL allowlist and no arbitrary remote fetch, language/file fixtures with expected ranges, unsupported and oversized files, Unicode/newline line numbering, path traversal, snippet redaction/bounds/truncation, duplicate concepts, version-sensitive examples, ambiguous AI output, stale snapshot references, zero code execution, and prompt injection in comments/README/commits. Track precision with reviewed fixtures rather than unsupported certainty claims.
